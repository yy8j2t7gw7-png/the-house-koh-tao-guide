# Meta Registration Owner Alerts — v5.11.45

## Final approved template contract

This document matches the templates actually created in Meta. The Worker payloads in this release are aligned to these exact BODY variable counts and quick-reply buttons.

All registration alerts route to the two configured owners only. No passport image, passport number, guest name, nationality, date of birth, gender, confirmation code, stay token, phone number or other identity-document content is sent through WhatsApp.

## Template 1 — reminder alerts

**Template name**

`house_registration_admin_alert_v1`

**Category**

Utility

**Language**

English (`en`)

**Header / footer**

None

**BODY — exactly 1 variable**

```text
Hi Admin,

Guest registration requires attention.

{{1}}

Please review the registration status and confirm below.
```

**Quick reply button — exactly 1**

`Received`

The Worker sends the whole human-readable room/status sentence as `{{1}}`.

Examples generated by the Worker:

```text
Room 8: No passports have been uploaded yet. 2 passports are still missing. Please check with the guest.
```

```text
Room 5: 1 of 2 passports has been uploaded. 1 passport is still missing. Please check with the guest.
```

```text
Room 11: The passport was uploaded more than 24 hours ago and is still not marked as TM30 registered. Please complete the TM30 registration.
```

This template is used for:

- the 20:00 Bangkok check-in-day reminder when zero required passports have arrived;
- the 20:00 Bangkok check-in-day reminder when only some required passports have arrived;
- the 24-hour TM30 overdue reminder.

Pressing `Received` acknowledges the exact operational alert. It does not change passport or TM30 state.

## Template 2 — immediate passport received alert

**Template name**

`house_registration_admin_alert_actions_v1`

**Category**

Utility

**Language**

English (`en`)

**Header / footer**

None

**BODY — exactly 2 variables**

```text
Hi Admin,

A passport has been uploaded for a guest staying at The House.

Room: {{1}}

Upload status:
{{2}}

Please confirm below when received, or mark the passport as TM30 registered once completed.
```

**Quick reply buttons — exactly 2**

1. `Received`
2. `TM30 uploaded`

Runtime variables:

- `{{1}}` = room number only, for example `11`;
- `{{2}}` = non-sensitive progress text, for example `1 of 1 required passport has been uploaded.`

`Received` acknowledges the exact alert only.

`TM30 uploaded` is accepted only from an authorized owner recipient. The server follows the durable alert-to-passport link, marks that exact passport TM30 registered in Owner Admin, and resolves the alert. It does not trust a passport identifier from WhatsApp.

## Reminder behavior

### Check-in day at 20:00 Bangkok time

The hourly Worker evaluates local Bangkok time. If foreign-passport registration is incomplete:

- 0 of N received: owners are told that no passports have been uploaded and how many are missing;
- partial progress: owners are told exactly how many have arrived and how many remain missing;
- complete: no reminder is sent.

Thai-ID registration and owner-managed in-person states are excluded from this foreign-passport reminder.

A successful owner delivery marks the reservation reminder sent. If Meta accepts no owner delivery, the claim is released so a later hourly run can retry.

### TM30 overdue after 24 hours

Each stored foreign passport becomes due when its upload timestamp is at least 24 hours old and it is still not marked TM30 registered.

The reminder is per passport. A successful owner delivery prevents repeated reminders for that passport. If delivery fails completely, the claim is released for retry.

Marking the passport TM30 registered either manually in Owner Admin or through `TM30 uploaded` prevents the 24-hour reminder.

## Runtime configuration

`wrangler.jsonc` maps both templates:

```text
WHATSAPP_REGISTRATION_TEMPLATE_NAME=house_registration_admin_alert_v1
WHATSAPP_REGISTRATION_ACTION_TEMPLATE_NAME=house_registration_admin_alert_actions_v1
```

`WHATSAPP_STAFF_ACTIONS_ENABLED=true` must remain enabled for the immediate passport-received action template.

No new recipient secret is required. The existing `WHATSAPP_ALERT_RECIPIENTS` configuration continues to supply the two owner recipients through the owner route.

The hourly cron remains:

```text
0 * * * *
```

The cron is UTC at Cloudflare, while the code explicitly evaluates Bangkok local date/hour for the 20:00 rule.
